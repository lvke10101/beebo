   - Added ALLOWED_VIDEO_EXTENSIONS = {'mp4', 'mov', 'avi', 'webm', 'mkv'}
   - Added MAX_HIGHLIGHT_SIZE = 25 * 1024 * 1024  # 25MB

2. DATABASE MIGRATION (Lines 126-138):
   - Added highlights table creation in init_db()
   - Added idx_highlights_user index for performance

3. NEW ENDPOINTS (Lines ~527-~700):
   
   a) GET /api/users/:id/highlights
      - Returns user's highlights as JSON array
      - Response shape: {id, title, kind, cover, created_at}
      - Ordered by created_at ASC (oldest first)
   
   b) POST /api/highlights
      - Multipart form upload (media + title)
      - Validates file type, size (25MB max), title (20 chars max)
      - Infers kind from mimetype (image/* → photo, video/* → video)
      - Stores file with UUID filename in static/uploads/
      - Returns created highlight object
   
   c) DELETE /api/highlights/:id
      - Auth required, ownership validated
      - Deletes database row and media file
      - Returns {success: true}

================================================================================
DATABASE SCHEMA:
================================================================================

Table: highlights
  - id (INTEGER PRIMARY KEY AUTOINCREMENT)
  - user_id (INTEGER NOT NULL, FK to users)
  - title (TEXT NOT NULL)
  - kind (TEXT NOT NULL, CHECK: 'photo' or 'video')
  - media_url (TEXT NOT NULL)
  - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

Index: idx_highlights_user ON highlights(user_id)

================================================================================
VALIDATION RULES:
================================================================================

✓ Authentication required for all operations
✓ Title: Required, max 20 characters
✓ File type: image/* → photo, video/* → video
✓ File size: Max 25MB
✓ Allowed image extensions: png, jpg, jpeg, gif, webp
✓ Allowed video extensions: mp4, mov, avi, webm, mkv
✓ Ownership: Users can only delete their own highlights
✓ File cleanup: Media files deleted when highlight is deleted
